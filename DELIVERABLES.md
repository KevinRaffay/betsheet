# Deliverables ledger

One row per PR-sized deliverable. **Every PR updates its own row in the same
PR.** Status values: planned / in progress / in review / merged. This file is
tracked externally — it must always reflect actual state.

**QA rule (2026-09-02):** a deliverable merged from the `qa` branch carries a
`-QA` suffix on its ID (e.g. `D44-QA`) here, in CLAUDE.md's feature-status
table and wherever the ID is cited; the plain D-sequence is reserved for the
planned deliverables and a QA row never reuses or blocks a number.

**Split-ID rule (2026-09-04):** when two deliverables have ended up sharing a
number, they take `-A` / `-B` suffixes in merge order (`D77-A` is PR #107,
`D77-B` is PR #108) rather than one being renumbered - a merged row's ID is
already cited in commits, PR descriptions and code comments, so moving it
breaks more than it fixes. Suffixed rows are updated everywhere the ID is
cited, exactly like the `-QA` rule above, and the shared number is not reused
again.

**Maintenance note (QA, 2026-09-02):** migration 014 was restored to its
recorded immutable contents after a digest mismatch. The tombstone-collision
repair lives in append-only migration 019; this correction does not introduce
a new deliverable.

with collapsible entries, fixed header/footer controls, a generation spinner,
and next-race navigation that advances from the race most recently saved. It
also shows payout estimates in preview, displays generation/save errors in the
affected race card, preserves model reasoning in saved allocations and keeps
that reasoning visible at the preview's compact size. The LLM prompt receives
stored external consensus, including Sports from the Basement.

Root cause: Node's watch mode restarts on any filesystem notification for a loaded module file, and on Windows libuv's ReadDirectoryChangesW filter includes attribute/security changes, so a metadata-only touch counts. Vite attaches its own error listener AFTER `configure` (verified in `node_modules/vite`), so its red stack still prints under ours - an attempted `removeAllListeners('error')` was therefore dead code and was dropped rather than left in, and monkey-patching vite's logger to hide the stack was rejected as hiding real errors. The proxy target also moves from `localhost` to `127.0.0.1`, matching the server's IPv4-only bind (invariant 10) - `localhost` resolves `::1` first on Windows.
